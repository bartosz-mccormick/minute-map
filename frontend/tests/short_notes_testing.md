# Frontend Testing Notes

Run commands from the `frontend` folder:

```bash
cd frontend
```

## Folder Structure

`tests/unit` contains fast Vitest tests. They test small pieces of logic without opening a real browser.

`tests/e2e` contains Playwright browser tests. They build and run the app, then check real app behavior in Chromium.

`tests/perf` contains Playwright performance tests. They are browser tests with timing / smoothness checks and are more sensitive to machine load.

`test-results` is generated by Playwright. It stores artifacts from browser runs, for example traces, screenshots, videos, and failure attachments. It is mainly created/updated by:

```bash
npm run test:e2e
npm run test:e2e:perf
```

Vitest unit tests do not normally write useful artifacts there.

## Unit Tests

Run all unit tests:

```bash
npm run test
```

Run unit tests in watch mode:

```bash
npm run test:watch
```

Run one unit test file:

```bash
npx vitest run tests/unit/components/hex-map.test.ts
npx vitest run tests/unit/components/maplibre-hex-layer.test.ts
npx vitest run tests/unit/components/poi/usePoiViewportSync.test.tsx
npx vitest run tests/unit/lib/binning.test.ts
npx vitest run tests/unit/lib/mobile-draw-scroll-lock.test.ts
```

What each unit file checks:

- `tests/unit/components/hex-map.test.ts`: map performance mode flags, diagnostic query params, overlay rendering decisions, and hex picking behavior.
- `tests/unit/components/maplibre-hex-layer.test.ts`: adding, updating, and cleaning MapLibre GeoJSON sources/layers for hex cells and selected hex cells.
- `tests/unit/components/poi/usePoiViewportSync.test.tsx`: POI zoom mode thresholds and viewport sync behavior; verifies it avoids expensive continuous move/zoom recalculation.
- `tests/unit/lib/binning.test.ts`: bin range creation and population-weighted bin summaries.
- `tests/unit/lib/mobile-draw-scroll-lock.test.ts`: mobile draw scroll-lock detection and cleanup of temporary body/html styles.

## E2E Tests

Run all E2E tests:

```bash
npm run test:e2e
```

This runs `npm run build`, starts `vite preview` on `127.0.0.1:4174`, and runs Playwright tests from `tests/e2e`.

Run one E2E file:

```bash
npm run build
npx playwright test tests/e2e/map-indicator-rendering.spec.ts
npx playwright test tests/e2e/map-performance-baseline.spec.ts
npx playwright test tests/e2e/poi-map-performance.spec.ts
```

What each E2E file checks:

- `tests/e2e/map-indicator-rendering.spec.ts`: opens the app, runs the default analysis, changes indicators, and verifies the hex map canvas visually changes.
- `tests/e2e/map-performance-baseline.spec.ts`: checks diagnostics/base-map mode where only the MapLibre surface should render.
- `tests/e2e/poi-map-performance.spec.ts`: verifies wheel zoom does not repeatedly reload POI parquet data or rebuild POI rows.

## Performance Tests

Run the performance test:

```bash
npm run test:e2e:perf
```

This runs `npm run build`, starts `vite preview` on `127.0.0.1:4175`, and runs the perf config.

Run the perf file directly:

```bash
npm run build
npx playwright test -c playwright.perf.config.ts tests/perf/map-zoom-performance.perf.spec.ts --workers=1
```

What the perf file checks:

- `tests/perf/map-zoom-performance.perf.spec.ts`: loads a large synthetic hex fixture, performs a zoom-out interaction, records frame timing, attaches metrics to the Playwright report, and fails if smoothness is outside the configured budget.
